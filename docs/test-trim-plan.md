**Status:** APPLIED 2026-09-05, as written, with these deviations and
findings. (a) The drive keeps one probe field the plan listed for
deletion, `tipShape`: S10 reads it, the popup's value being the session's
own setting through the strip's control. The atlas scenarios read the

and 666 lines by §5's own arithmetic (the estimate was off, not the cuts);

(f) `src/lib/mesh.js` is deleted with its test, the plan's option taken;
the centering and Y contract moved to `wedge-mesh.test.mjs` through
`wedgeMesh`. Numbers: unit 7,148 → 5,353 lines (`helpers.mjs` included),
347 → 218 cases; drive 5,141 → 2,825 lines, 320 → 81 checks, 164 → 20
sleeps, 31 → 1 imports from `src/`; goldens 8; SMOKE-TEST 72 → 21 items;
the README's test catalogue a paragraph and a rule list; test code to app

`goldens.sh check` twice in a row; `drive.mjs` 81 of 81. Line numbers
below are as of commit `ae8162c`, the tree the plan was cut against.

The ask: "i'm worried we're over testing... one thing we should NOT do is
be testing the behaviors of the Vintage Frames dependency... we also do
not need to test every single little thing." This plan takes the suites
down to what earns its run, in four phases, each with a gate. Nothing
here touches the app's behavior; every cut is test code, test tooling
or the paperwork that describes them.

## 1. The target shape (this becomes the README's testing policy)

Four layers, each doing the one thing it is cheapest at:

1. **Node unit tests** for the pure code where bugs are silent and
   expensive: the visual-hull pipeline, the meshes, the rasterizers, the
   PNG format, undo, the document and library contracts. Dense there.
   For state slices, a few behavior tests, never the store discipline
   per setter. For layout arithmetic, the rules (placement, cascade,
   pin, the fixed point), never a number against a literal.
2. **`tools/drive.mjs`**, an integration smoke of user journeys: about
   25 scenarios, about 80 checks, a hard ceiling of 100. A check exists
   only when it crosses a boundary a unit cannot (IndexedDB, trusted
   input, the real canvas, the menu wiring, a reload) and names an
   outcome of the app's own: a store value, a texel, a stored record, a
   window opened, a handler having run.
3. **Golden screenshots** (`tools/goldens.sh` over `capture.sh`) for the
   look: dim or plain labels, dotted rules, header heights, ring ink,
   the DITL, the paper. Zero assertion code. A golden that changes on
   purpose is regenerated after an eye on the diff, which is the
   existing rule for minor UI changes.
4. **`docs/SMOKE-TEST.md`** for what none of the above can reach:
   chorded drags, feel, the cursor, browser zoom, the drop.

The rules, greppable where possible:

- **Never assert the kit.** No check reads a `[part=…]` rect to assert
  on it, counts `vf-*` elements, reads a `--vf-*` property, pins
  `resizable` / `scrollbars` / `header-height` / a size rect, asserts a
  drag or grow delta, or asserts DOM order after a raise. Locating a
  kit control through its part to drive it is fine.
- **The drive re-derives nothing.** It imports nothing from `src/` but
  the PNG chunk reader. Arithmetic is Node's; the drive checks that the
  app applied it (a resize lands where Arrange lands, read off the
  page).
- **One home per fact.** No constant pinned against a literal, no
  default parameter pinned, no dev-only URL hook tested, no guard that
  a retired feature stays absent, no literal UI copy.
- **Test the store once.** Two tests in `store.test.mjs`; no per-setter
  "silent when unchanged" or NaN assertions anywhere else.
- **A precondition is not a check.** A helper that cannot find its
  target throws; the run fails with a message, the count does not move.
- **No check per feature by default.** A change ships with a test when
  it adds a risk the gates do not cover. Commit messages do not report
  check or test counts.

## 3. Phase A: golden screenshots

`capture.sh` already gives byte-deterministic shots (fixed window, DSF 1,
a virtual-time budget, a fresh `--user-data-dir` per run so IndexedDB is
empty and no machine's saved docs leak into the frame). The missing piece
is a fixed list and a comparison.

**`tools/goldens.sh`** with two modes:

```sh
tools/goldens.sh update [port]   # shoot every golden into docs/goldens/<name>.png
tools/goldens.sh check  [port]   # shoot into a temp dir, cmp each against docs/goldens/, exit 1 naming any mismatch
```

It calls `capture.sh shot` per entry with the same flags capture.sh
already pins, and prints the `cmp` result per name. The list lives in
the script, one line per golden, and every URL carries
`&now=2026-08-24T19:27` so the clock is frozen.

The set, eight shots:

| ------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `boot-about`       | `?fresh=1&about=1`                             | The About box over the bare desktop in the Finder role; the menu bar and clock                         |

Rules for the set:

- **Shoot each twice before committing** and `cmp` the pair. A shot
  that differs between two runs is not a golden; drop it rather than
  compare with a tolerance.
- **A golden changes only in a commit that changed the look on
  purpose**, after the diff has been eyeballed. A kit bump will move
  pixels; regenerate after review. That cost is real but smaller than
  today's: the drive's geometry pins broke on every kit release too, and
  each needed a rewrite (the 0.6.0 upgrade doc records the `flush` pin
  going).
- `docs/goldens/` holds the PNGs (the repo already carries
  `docs/car.png`). Eight 1000×850 shots of mostly flat 1-bit chrome are
  small.

`stamp`.

**`main()` becomes a list of scenario functions**, one per row of §4.3,
each `async function sN_name()` with its own `section()`, called in
order from a short `main()`. One file still (the zero-dependency
property is worth keeping); a `tools/drive/` split is an option later,
not part of this plan.

**Imports from `src/`:** `readTextChunks` only. The 30 other oracle
imports go with the checks that used them.

**Sleeps:** every `await sleep(N)` that follows an input is replaced by
a `waitFor` on the outcome the next check reads, where one is
observable (a tool changed, a window appeared, a texel painted, a
dialog opened, the stamp changed). A sleep stays only where nothing is
observable (the kit's menu blink). Target under 40, from 164.

**Preconditions throw.** `bareSpot()` and its kin throw when they find
nothing; the four "found a bare patch of desktop" checks and the
"found a visible patch of the untitled window" check go.

## 8. Judgment calls, recorded

- **Goldens cost a regeneration on every kit release.** Accepted: the
  drive's geometry pins cost a rewrite on every kit release already, and
  a golden diff is reviewed by eye, which is the standing rule.
- **The drive keeps the readiness contract and the phantom-reload
  absorption.** Neither is a check; both are what makes the run honest.
- **Chorded and right-button drags stay manual.** Headless Chrome wedges
  on them (the header's trap 3); the Node suites hold their semantics.
- **The layout arithmetic is still tested, in Node.** The drive stops
  re-deriving it and keeps one page-level comparison: a resize lands
  where Arrange lands.
- **`lib/mesh.js`** is dead in the app. The plan keeps one test for it
  per the Sep 4 decision; deleting the module is the cleaner end and is
  the user's call.
- **What is lost on purpose:** the ratchet pin (its mechanism is gone),
  the DITL glyph-fit pin, the dim and dotted checks, the exact
  within-tolerance palette pairs, the light-DOM placement of the Colors
  dialog (a comment in `sm-color-picker.js` already explains it; a
  golden with the dialog open would show the cursor over it if it ever
  regressed, and one can be added then).
